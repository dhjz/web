当前页面缺少 SharedArrayBuffer（未跨域隔离），转换一定会失败。 ffmpeg-core.wasm 是多线程（pthreads）构建，FFmpeg 6.1 的 CLI 每条输入流都要起一个解码线程， Emscripten 的线程依赖 SharedArrayBuffer，而浏览器只在跨域隔离的页面里提供它 （响应头 COOP: same-origin + COEP: require-corp）。 本目录的 coi-serviceworker.js 会用 Service Worker 自动补上这两个头， 首次访问会自己刷新一次（静态托管 dufs / nginx 默认配置 / GitHub Pages 都适用）。
仍然看到这条提示，通常是： ① 地址不是安全上下文 —— 需要 https:// 或 http://localhost / http://127.0.0.1，局域网 IP 的 http 不行（既没有 Service Worker 也没有 SharedArrayBuffer）； ② 浏览器禁用/不支持 Service Worker； ③ 页面嵌在 iframe 里，而顶层页面没有隔离。 日志里出现 pthread_create() failed: Resource temporarily unavailable 就是这个原因。

2. 转换与下载

输入是已选文件对应的虚拟路径：第 1 个 /input/input.bin， 第 2 个起 /input/f2.bin、/input/f3.bin …（见左侧文件列表）。 产物请写到 /output/ 下。 支持多产物，见「常见命令」。产物名默认跟随输入文件：写 /output/out.mp3 会下载成 输入名.mp3； 自己起的名字（如 a_0-2s.wav）则原样保留。 一次转很多文件时，建议自己加上 -filter_threads 1（有 -filter_complex 时再加 -filter_complex_threads 1）： 图形模式会自动加，它能避免浏览器同时启动一堆 wasm 线程 worker 而卡住。
