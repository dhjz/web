天气接口怎么用

鱼戏莲叶间右上角那格天气，后端是 Open-Meteo——免费、不用注册、不用 API key、CORS 全开， 浏览器里直接 fetch 就能取。真正干活的只有两个接口：一个把「城市名」换成经纬度，一个拿经纬度换天气。 这个页面把两个接口拆开讲清楚，并且能直接点着玩。

一句话版本：城市搜索 → 拿到 latitude/longitude → 拿这两个数查天气。没有第三步，也不需要 token。

一、先动手：搜索 → 查天气

下面那条灰线是请求日志：每发一次请求，把完整 URL 和返回码打出来，方便你对着看参数长什么样。 搜索结果里纬度、经度各自一个按钮，点哪个复制哪个；查完天气，地名下面也留了同一对按钮。

二、接口 1：城市搜索（地名 → 经纬度）

地址

https://geocoding-api.open-meteo.com/v1/search

它和查天气的不是同一个域名，别混：搜索在 geocoding-api，天气在 api。

参数

参数说明
name 必填 地名或邮编。可以带限定词消歧：Paris, France、洛杉矶, California。 两个字才会走精确匹配，三个字以上走前缀匹配；空串和单字一律返回空结果。
count 可选 返回几条，默认 10，上限 100。池子里用 6。
language 可选 语言，默认 en。写 zh 才回中文名（杭州而不是 Hangzhou）。小写。
format 可选 json（默认）或 protobuf。
countryCode 可选 ISO 两位国家码，用来硬过滤。例：CN。

请求

https://geocoding-api.open-meteo.com/v1/search?name=%E6%9D%AD%E5%B7%9E&count=6&language=zh&format=json

中文一定要 encodeURIComponent，别把原字符直接拼进 URL。

返回（真实响应，截了两个结果里的一个）

{
  "results": [
    {
      "id": 1808926,
      "name": "杭州",              // 你要显示的城市名
      "latitude": 30.29365,        // ↓ 这两个是下一步的输入
      "longitude": 120.16142,
      "elevation": 12.0,
      "timezone": "Asia/Shanghai",  // 城市时区，做时钟很有用
      "feature_code": "PPLA",       // 地名类型：PPLC=首都 PPLA=省会 PPL=普通地名
      "country": "中国",
      "country_code": "CN",
      "admin1": "浙江",             // 省/州，重名时靠它区分
      "admin2": "杭州市",
      "population": 11936010
    }
  ],
  "generationtime_ms": 0.14
}
有一堆坑要留意：
① 没有 results 键不代表失败——搜不到就直接不返回这个键，只给一个 generationtime_ms。 所以代码里必须写 data.results || []，直接 data.results.forEach 会炸。
② 重名严重。杭州 会回来两个：浙江的（省会）和四川甘孜的（海拔 2321 米）。所以结果里要显示 admin1， 让人自己挑，别默认取第一个还怪接口不准。
③ 返回的 latitude/longitude 已经有小数位了，别自己 Math.round——0.1 度大概 11 公里，一取整就换城市了。

三、接口 2：查天气（经纬度 → 天气）

地址与最简调用

https://api.open-meteo.com/v1/forecast?latitude=30.29&longitude=120.16

两个必填参数就 latitude / longitude，其余全可选——不写变量的话默认回一坨 hourly 全量数据，太大。所以要什么点什么。

鱼塘里用的那一条

https://api.open-meteo.com/v1/forecast
  ?latitude=30.29365
  &longitude=120.16142
  &current=temperature_2m,weather_code,wind_speed_10m      ← 实时
  &daily=weather_code,temperature_2m_max,temperature_2m_min ← 每日
  &timezone=auto                                          ← 按当地时区切「今天」
  &forecast_days=3                                        ← 今天/明天/后天

这条 URL 里每个参数在干什么

参数说明
current= 「此刻」的变量，逗号分隔。要什么点什么，多一个多一份体积。
temperature_2m 2 米气温（°C）、weather_code 天气代码（数字，见下）、 wind_speed_10m 10 米风速（km/h）。
daily= 「每天」的变量，回的是数组，长度 = 天数。temperature_2m_max/min 当天最高/最低。
timezone=auto 不写会按 GMT 切天，北京时间的「今天」可能变成昨天。写 auto 让它按经纬度自动定， 返回里带 timezone 和 utc_offset_seconds。也可以硬写 Asia/Shanghai。
forecast_days= 要几天，默认 7，最长 16。池子要 3 天。
单位 默认公制（°C、km/h、mm）。要华氏就加 &temperature_unit=fahrenheit， 风速 &wind_speed_unit=ms。返回里的 *_units 会告诉你实际单位，别硬编码。

返回（真实响应，2026-11-15 12:45 杭州）

{
  "latitude": 30.263618,          // 注意：回来的坐标是网格点，跟你要的不完全一样，正常
  "longitude": 120.14051,
  "timezone": "Asia/Shanghai",
  "utc_offset_seconds": 28800,
  "elevation": 10.0,

  "current_units": { "temperature_2m": "°C", "weather_code": "wmo code", "wind_speed_10m": "km/h" },
  "current": {
    "time": "2026-11-15T12:45",
    "interval": 900,              // 这组值代表过去 15 分钟
    "temperature_2m": 18.9,
    "weather_code": 3,              // 3 = 阴
    "wind_speed_10m": 13.2
  },

  "daily_units": { "weather_code": "wmo code", "temperature_2m_max": "°C", "temperature_2m_min": "°C" },
  "daily": {
    "time": ["2026-11-15", "2026-11-16", "2026-11-17"],
    "weather_code": [51, 3, 80],
    "temperature_2m_max": [19.0, 19.3, 16.4],
    "temperature_2m_min": [14.5, 13.1, 12.6]
  }
}
三个容易写错的地方：
① daily 里的每一列是「按 daily.time 这个顺序对齐的数组」，不是一个对象数组。 想拿第 2 天的最高温是 daily.temperature_2m_max[1]，别去找 daily[1]。
② 天气代码是数字，接口不给你中文。0~99 的 WMO 码，中间一堆空缺（比如 4~44 没有）， 必须自己建映射表，而且要有兜底 || "多云"，不然遇到没写的码页面上就是 undefined。
③ 报错也是 200 之外的正经 JSON：参数错会返 400 + {"error":true,"reason":"..."}。 res.ok 为假时别直接 res.json() 当成功数据用，先把 reason 打出来。

WMO 天气代码对照表（接口原始定义，全量）

鱼塘里的映射是它的一份中文简化版（wallpaper/pond/ui.js 的 weatherName()），并且 weatherEffect() 把这些码再归类成 晴/雨/毛毛雨/雪/雾 五种，用来驱动池塘里的天气特效。 96/99（雷暴带冰雹）只有 DWD ICON、UKMO 这类明确预报冰雹的模型会报，其他模型给的是 95/97。

四、接口 3：定位（可选，兜底用）

要「自动定位」，其实叠了三层，一层失败往下一层：

层用什么拿到什么
1 navigator.geolocation（浏览器原生，不是接口） 精确坐标（约 10 公里）。要用户授权，WebView2 里还得外壳放行——见 config.toml 的 allow_geolocation。
2 https://ipwho.is/ 按出口 IP 猜城市，误差能到省。不用参数、不用 key、CORS 全开，就是慢一点。
3 写死一个 杭州 30.2741, 120.1551。全失败时至少别让页面上是空的。 
// 第 2 层，够用了
const ip = await (await fetch("https://ipwho.is/")).json();
// ip.success 为 false 就是失败（限流/内网），别只看有没有 city
const { city, latitude, longitude } = ip;
{
  "ip": "175.178.127.92",
  "success": true,
  "city": "Guangzhou",        // 注意：英文，要中文得再走一次城市搜索
  "latitude": 23.1166691,
  "longitude": 113.2529533,
  "country": "China",
  "timezone": { "id": "Asia/Shanghai" }
}
一个真实的坑：逆地理编码接口已经没了。
代码里原来还有一步 https://geocoding-api.open-meteo.com/v1/reverse?latitude=..&longitude=..， 想「坐标 → 城市名」。但这个端点现在恒返回 404 （{"error":true,"reason":"Not Found"}，官方文档里也已不列它）。 所以那段 try/catch 每次都在走 catch，定位得到的名字永远落在 "当前位置" 或 IP 给的英文名上。 兜底写法：拿 IP 的 city 再走一次城市搜索换中文名和准确坐标——池子里已经在这么做了。

五、两个接口共通的规矩

不用 key，但有限流

免费版（非商用）限制：每分钟 600 次 / 每小时 5000 次 / 每天 10000 次 / 每月 30 万次。 个人壁纸随便用。限流信息在响应头 x-ratelimit-remaining 里，被拦了看 retry-after。

响应头 CORS 全开

access-control-allow-origin: *，所以纯静态页面（file:// 也行）直接 fetch 不需要代理。 这也是为什么这个 HTML 能双击就打开用。

可以缓存

搜索接口 cache-control: public, max-age=86400（一天），城市名基本不变。 天气接口自己有分钟级缓存。池子里的做法：结果存 localStorage，默认 120 分钟刷一次， 时长写在 data.json 的 weatherCacheMinutes。

要署名

数据 CC BY 4.0，用了得给出处。池子右上角那行「天气数据 · Open-Meteo」就是干这个的，别删。 商用要买 plan，走 customer-api.open-meteo.com + &apikey=。

六、把这段抄进你的代码

最小可用版本，复制就走，不依赖任何库：

// 城市名 → { name, lat, lon, tz }
async function findCity(name) {
  const url = "https://geocoding-api.open-meteo.com/v1/search?name="
    + encodeURIComponent(name) + "&count=6&language=zh&format=json";
  const res = await fetch(url);
  if (!res.ok) throw new Error("搜索失败 " + res.status);
  const data = await res.json();
  const list = data.results || [];          // 搜不到时这个键不存在
  if (!list.length) throw new Error("没有找到这个城市");
  const hit = list[0];
  return { name: hit.name, lat: hit.latitude, lon: hit.longitude, tz: hit.timezone };
}

// 经纬度 → 实时 + 3 天
async function getWeather(lat, lon) {
  const url = "https://api.open-meteo.com/v1/forecast?latitude=" + lat
    + "&longitude=" + lon
    + "&current=temperature_2m,weather_code,wind_speed_10m"
    + "&daily=weather_code,temperature_2m_max,temperature_2m_min"
    + "&timezone=auto&forecast_days=3";
  const res = await fetch(url);
  if (!res.ok) {
    const err = await res.json().catch(() => ({}));
    throw new Error(err.reason || ("天气查询失败 " + res.status));
  }
  return res.json();
}

// 用
const city = await findCity("杭州");
const w = await getWeather(city.lat, city.lon);
console.log(city.name, w.current.temperature_2m + "°C", WMO[w.current.weather_code]);

七、如果拿不到数据，按这个顺序查

现象多半是
控制台 Failed to fetch 断网，或被公司网络/代理拦了。先 curl 一下这两个域名。
搜城市有结果，查天气没有 经纬度写反了。参数名是 latitude 在前、longitude 在后，但很多人赋值时对调。
400 + Latitude must be in range of -90 to 90 把经度当纬度传了，或者 parseFloat 得到 NaN 拼进了 URL。
400 + Invalid value: ... from invalid String value foo 变量名拼错。是 weather_code 不是 weathercode，是 temperature_2m 不是 temp。
reason: "Not Found"（/v1/reverse） 这个端点已经下线，别用了，改用 IP 猜城市 + 城市搜索兜底。
「今天」比实际早一天 漏了 timezone=auto，被当成 GMT 了。
天气代码显示不出中文 忘了建映射表。接口只给数字。
